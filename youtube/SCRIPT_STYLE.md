# 대본 작성 규칙 (AI 음성 기준, 피드백으로 계속 갱신)

## 채널 코너 (주 2편)
- **A. 주식 궁금증, 숫자로 풀기** — 화제가 된 종목·ETF, 늘 궁금하던 질문을 실제 데이터로 백테스트하고 인사이트를 얻는다.
  레딧·유튜브의 성공담/실패담은 출발점이 아니라 "이런 얘기 들어보셨죠?" 수준의 **대중 여론**으로만 가볍게 언급.
- **B. 매매법 해부** — 대가 또는 온라인에서 핫한 매매법을 규칙으로 옮겨 백테스트하고 뜯어본다.

## 말투
- 구어체: "자,", "근데요", "솔직히요", "아 진짜", "~거든요/~예요/~죠"
- 짧은 문장과 긴 문장을 섞는다. 반전·숫자 공개 직전에는 쉼표로 한 박자.
- 특정 종목 매수·매도 권유 금지. "~해야 한다" 대신 "데이터로는 ~였다".

## AI 음성이 어색해지는 것 (실제 피드백)
| 하지 말 것 | 이유 / 대신 |
|---|---|
| 문장 안 따옴표 `'2년 만에 30배'는요` | 따옴표 앞뒤로 쉬어서 "는 … 요"처럼 끊김 → 따옴표 없이 쓰기 (음성에서는 자동 제거됨) |
| `1억 8천`, `1,000만` 을 숫자 그대로 | "1 억 8 천"처럼 끊어 읽음 → 음성에서는 자동으로 "일억팔천", "천만"으로 바꿔 읽게 처리됨 |
| `302배` 같은 큰 배수 강조 | "삼백, 이 배"처럼 끊어 짚어 주기 (발음 사전 `SAY`에 등록) |
| 쉼표를 안 쓰고 길게 이어 쓰기 | 이 목소리는 쉼표에서 안 쉬던 문제 → 쉼표마다 짧은 쉼 자동 삽입. 쉬고 싶은 곳엔 쉼표 |
| 영어 약어 그대로 | TQQQ→티큐큐큐, SQQQ→에스큐큐큐, SOXL→속슬 등 발음 사전에 추가 |

| 횟수 `19번 중 17번` | 음성에서 자동으로 고유어로: 열아홉 번, 열일곱 번, 스무 번째, 첫 번째 |
| 연도·기간 `1990년엔`, `76년이지만` | 숫자와 조사를 끊어 읽음 → 자동으로 "천구백구십년엔", "칠십육년이지만" |
| 쉼표 숫자 `7,568포인트` | "칠 오백육십팔"로 끊어 읽음 → 자동으로 "칠천오백육십팔포인트" |
| `76년 치`, `다음 해`, `전 해` | 띄어서 끊김 → 자동으로 붙여 읽기(년치, 다음해, 전해) |
| `1등` | 자동으로 "일뜽" |
| 날짜 `3월 16일엔`, `10월 6일에` | "16일 / 엔"으로 끊김 → 자동으로 "삼월 십육일엔", "시월 육일에" (6월=유월, 10월=시월) |
| 금액 `2억 4천8백만 원`, `3천1백7십만 원` | 끊어 읽거나 "삼천일백"으로 읽음 → 자동으로 "이억사천팔백만", "삼천백칠십만" (1 앞의 일 생략) |
| `5조 달러` · `AMD와 LSI 로직` · `세가` | 자동으로 "오조달러" (N조 달러 붙여 읽기) · 에피소드 say: "에이엠디와 엘에스아이로직", "쎄가" |

새로 발견한 어색한 발음은 `engine/tts.py` 의 `SAY` 사전이나 에피소드 `tts.say` 에 추가한다.

## 썸네일 (tools/thumbs.py, 에피소드 yaml `thumbs:`)
템플릿 7종(모두 채널 고유 디자인): calc(계산기 LCD) · receipt(백테스트 영수증) · clipping(가상 신문 스크랩+도장)
· diagonal(대각선 분할) · question(진짜일까?) · big_number(큰 숫자) · vs_numbers(숫자 대비)
- 다른 채널 썸네일의 구도·배색·소품 배치는 따라 하지 않는다. 레퍼런스에서는 '문구 공식'만 참고.
- 문구 공식: "~해라!", "~였다는데 진짜일까?", "~ 다 알려준다", "~ 따라만 해라", "~ 미쳤다…!"
  → 매수 권유로 읽히지 않게 따옴표·물음표로 '남들이 하는 말' 형태로.
- 같은 템플릿을 연속 두 편에 쓰지 않기.

## 훅 비주얼 (type: punch) — 롱폼당 3~6번만
- 평소 톤(어두운 남색 슬라이드)은 그대로 두고, **핵심 숫자가 터지는 순간**에만 컬러 풀스크린 카드로 '쾅'
- tone: up(빨강·좋은 결과) / down(파랑·나쁜 결과) / gold(노랑·반전·의외의 사실)
- `{type: punch, tone: up, label: "버블기 제외 · 1년 뒤", big: "14번 중 14번", sub: "평균 +46.9%", narration: [...]}`
- 쇼츠 커버도 같은 디자인: `cover: {style: punch, tone, top, label, big, sub}` → 쇼츠마다 다른 색·숫자로 차별화

## 에디토리얼 장면 (engine/editorial.py) — 다큐·PPT 느낌의 변주
- 배경 `bg`: `{kind: chart, series, start, end, log}`(실제 차트를 어둡게 깐 배경) · `{kind: grain, tone: navy|ink|rust|olive|plum}` · `{kind: calendar, hl: [NOV, ...]}`
- 공통: `kicker`(노란 작은 글씨) + `title`(흰 큰 제목, `highlight` 노랑) + `credit`(오른쪽 위 출처)
- `knockout` 거대한 단어 안에 차트가 비침 · `timeline` 눈금+구간 강조+태그 · `grid` N칸 중 K칸 색칠(연도·사람 아이콘) · `hbars` 가로 막대 비교 · `profile` 곡선 일부 구간 노랗게 · `infobox` 노란 띠 정보 박스
- `poster` 컬러 포스터(tone: rust|teal|mustard|navy|plum|sage) + 캔들 무늬 띠 + 실제 지수 흐름으로 만든 검은 산 실루엣 + `pin`(점선 라벨) + `figure`(이모지를 검은 실루엣으로: turkey, bull, bear, eagle, runner, pumpkin, capitol…)
- `usmap` 미국 지도(주별 색칠 `states`, 아래 제목, 오른쪽 아래 대비 막대 `bars`)
- 에피소드에 `series_tag: "..."` → 로고 옆 주제 태그
- 기존 남색 슬라이드와 섞어 쓰기: 한 편에 에디토리얼 8~12장 + 펀치 3~6장 + 나머지 기존 슬라이드

## 썸네일 원칙 (EP009 피드백)
- **답은 썸네일에 쓰지 않는다.** 결과 숫자 · 결론은 `???`, `?억`, `-??%`, "지금은?", "얼마?"처럼 비워 둔다. 질문 · 대비 · 과거 상황만 보여 준다.
- 8종: calc · receipt · clipping · diagonal · question · big_number · vs_numbers · **silhouette**
- **silhouette**(인물 편 필수): 얼굴 없는 상반신 실루엣 + 테두리 빛 + 큰 물음표 + 회사를 암시하는 아이콘(예: 칩). 실제 회사 로고는 쓰지 않는다(상표). 사물 편은 이모지 실루엣(호박 · 돈주머니 등)
- 문구: 과거의 바닥("식당 접시닦이 소년", "망하기 30일 전") ↔ 현재를 질문으로("지금은?")

## 롱폼 기본 규칙 (EP009 피드백)
- 길이: **8분 30초 ~ 10분**
- "사라는 영상 아닙니다" 장면은 넣지 않는다 (면책은 설명란 · 화면 오른쪽 위 · 아웃트로에 이미 있음)
- 어두운 versus 카드(2개 숫자 비교)는 한 편에 1~2개까지. 나머지는 duel(종이 카드) · frames(금테 액자 차트) · kpi · hbars · isobars · capsule · ticket · grid · poster 로 변주
- 포스터 장면엔 해 · 실루엣 동물(figure) 넣지 않는다 (엔진에서 제거됨). 대신 산이 그려지는 모션 + 앞 점 파동 + ridge.money 로 잔고 표시

## 쇼츠로 잘라 쓸 구간 = 처음 보는 사람도 이해되게 (EP010부터)
- 롱폼을 쓸 때 쇼츠 후보 구간(3곳)의 **첫 문장에 주어를 다시 말한다**: "엔비디아는 1996년…", "S&P500에 목돈을 한 번에 넣으면…"
- 대명사 · 앞 장면 의존 표현으로 시작하지 않기: "그런데", "그 회사는", "이번엔", "2번째로" ✗
- 각 쇼츠 구간 = [한 줄 맥락(누가 · 무엇)] → [질문] → [숫자] → [반전] 을 30~55초 안에 완결
- episode.yaml shorts 에는 `hook:` 문장을 따로 둘 수 있게 → 쇼츠 맨 앞 1~2초에 큰 글씨 + 음성으로 맥락 한 줄 추가

## 쇼츠 썸네일 = 롱폼의 펀치(훅) 장면 (EP010부터)
- 쇼츠 썸네일은 영상 속 펀치 장면이 그대로 쓰이므로, 펀치 장면에 **쇼츠 제목의 핵심이 큰 글씨로** 보여야 한다
  - label(위 작은 줄)도 크게(64~72) · big 은 쇼츠 제목의 핵심 단어("49.7억", "CUDA 10년 베팅", "11월에 사서 5월에 팔면?")
  - 쇼츠 구간마다 펀치 장면 1개를 반드시 넣고, 그 문구 = 쇼츠 제목과 같은 말로
- 단, 롱폼 톤앤매너(어두운 남색 + 노랑 강조)를 해치지 않는 선에서

## 다큐 스토리텔링 (EP010부터)
- 롱폼마다 **역사 · 속담 · 명화 · 소설 · 신화** 중 하나를 주제와 자연스럽게 엮는다 → 다큐멘터리 주식 채널 느낌
- 오프닝 훅이 가장 좋고, 어려우면 중반 반전 · 결말에 넣는다. 억지 연결 금지 — 숫자를 이해하는 데 실제로 도움이 될 때만
- 이미지: 퍼블릭 도메인 · CC 명화/삽화/사진(위키미디어 공용) + 출처 표기. 처음과 끝을 같은 이야기로 묶으면(수미상관) 더 좋다
- 예) EP010: "고래 싸움에 새우 등 터진다"(오프닝) · 『피터 팬』의 그림자(한·미 디커플링) · 3억 년 살아남은 새우(결말)

## 썸네일 고급화 (EP010부터)
- 8종 템플릿 모두 `photo:` 로 위키미디어 사진 배경 (diagonal은 a/b, vs_numbers는 left/right 각각 `photo`)
- 자동 마감: 시네마틱 색보정(채도↓ · 그림자 남색 · 밝은 곳 따뜻하게) + 비네팅 + 필름 그레인 + 얇은 금색 안쪽 테두리 (`finish: false`로 끄기)
- 글자 쪽은 자동으로 어둡게(shade) → 가독성 유지. 사진 출처는 설명란 [그림 · 사진]에 표기
- silhouette 템플릿: 사진에서 rembg로 따낸 실루엣(예: people/whale_cut.png) + 테두리 빛
- diagonal(대각선): 문구를 크게 · 직관적으로 — 라벨 110 · 숫자 300 · 위/아래 문구 120 (기본값). 문구는 6~8자 안으로 짧게 (EP010 피드백)
- 노란 · 크림 알약(pill) 안 글씨는 항상 검정 (엔진에서 자동)
- 자막: 한 문장(한 맥락)은 한 줄로 — 문장 단위로 나누고, 한 줄(36자)을 넘을 때만 쉼표 절 → 단어 순으로 나눔
- 포스터(크림 산) 장면 대신 `photoline`: 실제 사진(산 · 도시) 위에 지수 선이 그려지는 모션 차트
- 펀치(punch) 장면 · 쇼츠 커버: 단색 배경 대신 `photo:`(위키미디어) + 색보정 + 톤 색 형광펜 띠 — 롱폼 톤앤매너 유지하면서 직관적 · 진하게 (EP010 피드백). 마스코트는 사진 모드에선 기본 숨김

## 썸네일 화두 · 비교 (EP011 피드백)
- "~다면", "~넣었다면" 같은 **화두 문장은 썸네일에서 가장 크게** (190~200) — 보는 순간 각인되게
- 2~3개 비교는 한눈에: `versus3`(위 화두 띠 + 아래 3칸 사진 + VS 배지 + ?억) · `vs_numbers` · `diagonal`

## 비교 차트 변주 (EP011 피드백)
- `isobars`(3D 막대)는 좋지만 한 편에 1~2번만. 대신 섞기:
  - `leaderboard` 순위표(꼴찌부터 올라오고 1위가 마지막) · `waterfall` 폭포형 손익(출발 → +/- 항목 → 최종)
  - `hbars` · `kpi` · `duel` · `frames` · `capsule`

## 부동산 비교 원칙 (EP011 피드백)
- 아파트는 대출로 사는 상품: 주담대(LTV) · 전세(무이자 보증금, 갭투자) · 월세로 이자 충당을 반드시 반영
- 주식은 신용(고금리 · 반대매매)이라 사실상 레버리지가 어렵다는 차이를 각인
- 최종 비교는 "다 팔았을 때 손에 쥐는 돈": 취득세 · 중개비 · 이자 · 양도세(1주택 비과세 / 국내주식 비과세 / 해외주식 22%) · 아낀 월세
- 비교 썸네일의 가린 답은 **모두 같은 모양**으로 (?억 / ?억 / ?억 · 같은 색). ??억이나 한쪽만 빨강처럼 자릿수 · 색 · 크기로 승자가 티 나면 안 됨 (EP011 피드백)

## 이해도 장치 (2026-11-09 확정, 모든 영상)
- **원리 도식**: "아, 그래서 이게 필요하구나" 하는 구조를 그림으로 (type: flow — 입체 블록 노드 + 흐르는 화살표 + 아래 보조 그래프).
  참고 영상의 사막 배경 · 입체 그림체는 따라 하지 않는다. 우리 남색 · 금색 · 민트 팔레트.
- **문답(Q/A)**: 절망 · 반전 · 데이터 어디든 필요한 곳에 몇 번 (type: qa). 질문은 시청자 속마음 그대로.
  글자만 Q · A로 나열 금지 → 화보형: 왼쪽 실제 인물/조각 사진 누끼(듀오톤, 기본 로댕 '생각하는 사람') + 오른쪽 QUESTION/ANSWER + 작은 도식(compare 막대).
  채널 캐릭터 · 만화 실루엣 · 이모지는 쓰지 않는다 (고급스러움 우선).
- 대사 · 화면에 '절망' '희망'이라는 단어를 직접 쓰지 않는다. 맥락으로만 전달.
- 인용 카드(xpost)는 plain: true — 원문 핵심어 크게 + 아래 한글 한 줄 크게. '번역' 상자 쓰지 않음.
- 발음: 첫째·둘째·셋째는 쉼표 억양 없이 차분하게(say: '첫째, ' → '첫째 [pause] '), 수십 %씩 → 수십 퍼센트씩, 0원 → 영원.
- 질문형 문장은 쉼표로 잇지 말고 문장마다 물음표로 끊는다(끝음 차분하게).
- **도식화 자주 쓰기**: 원리 설명뿐 아니라 누군가의 주장 · 설명(CEO 발언, 증권사 논리, 정책 효과 등)도 flow 같은 도식으로 자주 풀어낸다. (EP013 원리 도식 호평)

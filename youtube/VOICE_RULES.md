2. `python render.py <ep> --stills` 또는 렌더 시 자동으로 `out/<ep>/음성점검.txt` 생성 → **확인 필요 0곳이 될 때까지 고친다.**

3. 사용자에게는 점검을 통과한 영상만 보낸다.

## 쉼 · 억양 (쓰는 법)
- **짧은 쉼은 ' / ' (0.12초), 긴 쉼은 ' // ' (0.3초)**: 조각마다 따로 녹음해 이어 붙인다. 자막에는 안 보인다. (롱폼 · 쇼츠 공통)
  예) `한 말은 이거였어요. // 한 달에? / 그렇게 많이 줘요?`
- 쉼표(,)는 짧은 쉼(pause short)으로 자동 변환. `[pause]`는 길고 어색해서 쓰지 않는다.
- 첫째 · 둘째 · 셋째는 자동으로 따로 떼어 차분하게 읽는다(`첫째, ` → `첫째 / `).
- **말꼬리 조각으로 끝내지 않는다**: "김장훈 씨처럼요." "900만 원까지요." → 끝 음정이 올라가 웃기게 들림.
  완결된 문장으로: "김장훈 씨도 그렇게 시작했어요." "900만 원까지 돼요." (점검기: 끝 음정 +18% 넘으면 경고. '처럼요'는 +33%였음)
- 질문은 쉼표로 잇지 말고 문장마다 물음표로 끊는다.
- 따옴표 속 대사는 앞에 ' // '로 한 박자 쉬고 시작한다.
- 한 문장이 30음절을 넘으면 쉼표나 ' / '로 호흡을 준다(점검기: 보통보다 25% 빠르면 경고).

## 짧은 단어 끌림
- 문장 첫머리 한 글자 지시어('이 돈을')가 길게 끌리면 에피소드 say로 '이, 돈을'처럼 짧은 쉼을 넣는다(자막은 그대로).

## 화면 싱크 (tools/sync_check.py · 렌더 때 자동 수정)
- 'on: N'은 **그 내용을 말하는 문장 번호**. 소개 문장("세 가지가 있어요") 다음 문장이 첫째다 → 목록은 보통 on: 2, 3, 4.
- 첫째 · 둘째 · 셋째가 있으면 그 문장 번호에 맞춘다. 렌더 때 자동으로 고치고 로그에 '싱크 수정'을 남긴다.

## 배경음 (engine/bgm.py · scored)
- 에피소드 `bgm.chapters`로 장마다 분위기: tense(쫄깃 · 긴장) · drive(흥미진진) · dark(무겁게 · 심장박동) · hope(밝게 · 설렘). 장이 바뀌면 2초 크로스페이드.
- 잔잔한 앰비언트(기본)는 쓰지 않는다 (EP014: "너무 잔잔하다").

## 자동 점검이 보는 것 (tools/voice_check.py)
- [글자] 변환 후 남은 숫자 · 영어 · 기호, 말꼬리 조각, 사전의 띄어 쓴 소수 · [pause]
- [소리] 쉼표 없는 곳의 0.3초 넘는 끊김 / 다른 문장보다 25% 넘게 빠르거나 느림 / 질문이 아닌데 끝 음정 상승(+18%)

## 목소리 한 사람 고정 (2026-11-17 사용자)
- 롱폼 · 쇼츠 · 두 채널 모두 내레이션은 **Gemini Umbriel 한 목소리로 끝까지**. 장면마다 목소리를 바꾸지 않는다.
- 예외: 쇼츠에서 **웃기게 피벗하는 순간**(반전 한 줄 · 개그 대사)만 다른 목소리 허용 (shortkit `__voice__`).
- 장면 단위로 따로 합성하면 같은 Umbriel이라도 톤이 살짝 달라질 수 있음 → STT 검사 때 톤 튀는 장면은 take를 바꿔 다시 뽑는다.

- 「N달」은 고유어: 6달 → 여섯 달, 10달 → 열 달 (2026-11-18 사용자 · 육 달 X). 달러는 제외.

## 한 영상 = 한 모델 (2026-11-18 사용자: 중간중간 톤 · 음색이 미세하게 다르다)
- 원인: 같은 Umbriel이라도 Gemini TTS 모델(flash ↔ pro)이 다르면 음색이 미세하게 달라짐. 하루 한도(17:00 초기화) 때문에 수정분만 pro로 자동 전환되면서 한 영상 안에 섞였음.
- 규칙: 한 영상 안에서는 **모델 하나로만**. 한도에 걸려 모델이 바뀌면 → 그 영상의 모든 장면을 같은 모델로 다시 만들거나, 한도가 풀린 뒤 원래 모델로 수정분을 다시 만든다.
- 일정상 섞일 수밖에 없으면 사용자에게 미리 알린다. 수정이 많을 영상은 한도 여유가 있을 때(17:00 직후) 작업 시작.

- 대책 ③ 음성점검.txt에 `[통일 장면 NN]` 줄 — 음높이 ±8% · 속도 ±18% · 크기 ±3dB 벗어나면 표시. 사용자에게 보내기 전에 0곳 만들기.
- 대책 ④ (2026-11-23 MBTI 편: ②만으로는 13곳 남음) 렌더에서 장면 음성을 다 만든 뒤 **에피소드 중앙값으로 장면별 보정** (`tts.unify_scenes`, 새 음성 요청 0):
  음높이 ±5% 넘으면 rubberband(목소리 결 유지, 길이 그대로라 화면 싱크 유지) → 한 번 더 재서 남은 차이 보정 · 크기 ±1.5dB 넘으면 volume · 속도 ±15% 넘으면 atempo(문장 시각도 같이 맞춤). 결과 13곳 → 0곳.
- 점검 도구 버그 수정: 예전 voice_check는 음높이 맞춤 전 take를 재서 실제 영상과 달랐음 → 이제 렌더와 같은 take + 같은 보정 결과를 잰다.
- 다시 렌더만 할 때는 `TTS_CACHE_ONLY=1` (캐시에 없는 음성은 만들지 않음 = 하루 한도 보호).
